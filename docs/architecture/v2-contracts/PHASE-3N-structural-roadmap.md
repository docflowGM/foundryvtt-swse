# Phase 3N structural roadmap — binding owner addenda

Recorded from the project owner's directives. These are scheduling and acceptance rules; none is started early. Each item is a bounded, behavior-preserving tranche: baseline/parity test first, extraction behind the stable public API, targeted tests, full rolling suite, architecture ratchet (no new cycles), commit, push, ledger update.

## Mandatory dependency chain
```
3D ActorEngine mutation-boundary reroutes (in progress)
 -> 3E–3M domain consolidation (stabilize consumers: 3C store, 3I customization, 3J vehicles/droids, 3L Holonet)
 -> 3N-AE  ActorEngine thin-facade completion
 -> 3N-TE  TransactionEngine thin-coordinator completion   (separate, reviewable change from 3N-AE; never edit both sides of the boundary at once)
 -> 3N-DC  DerivedCalculator mechanical accuracy and single authority
 -> 3N-PRQ Canonical prerequisite authority (+ registry supplement: PRQ-canonical-prerequisite-registry.md)
 -> 3N-PRG Unified progression mannequin
 -> rest of 3N, 3O dead-code pruning, 3P certification
```
Phase 3G only *prepares* the mannequin contract (audit existing previews, baseline tests); it does not implement it. Skills V2 is out of scope throughout.

## 3N-AE — ActorEngine (finding F-ACT-013; also F-ACT-001/003/007/008/015)
ActorEngine stays the one public mutation gateway; rules stay in domain engines; public methods unchanged (`updateActor`, `updateOwnedItems`, `updateEmbeddedDocuments`, `applyMutationPlan`, `applyDamage`, `applyHealing`, `spendForcePoints`, `spendDestinyPoints`, `recalcAll`, `updateActorFlags`, `unsetActorFlag`, …). No new god module; extracted modules never persist independently. Method-level inventory classes: KEEP_IN_FACADE, EXTRACT_PURE_HELPER, EXTRACT_INTERNAL_IMPLEMENTATION, DELEGATE_TO_EXISTING_DOMAIN_ENGINE, CONSOLIDATE_DUPLICATE, RETAIN_PENDING_PARITY, RETAIN_PENDING_OWNER_DECISION, VERIFIED_OBSOLETE. Order: AE.1 pure helpers/plan builders; AE.2 normalization via MutationNormalizationService/MutationBoundaryService; AE.3 flag + ActiveEffect internals (keep `recalc:false` semantics); AE.4 Force/Destiny Point ledgers (no second ledger); AE.5 mutation plans and recovery (F-ACT-003); AE.6 damage/healing/condition/Second Wind orchestration; AE.7 derived recalculation and governance (nested context, stamps, no new global patches); AE.8 facade cleanup. F-ACT-013 closes only on evidence (public API intact, no replacement god module, parity tests, cycles not increased); line count is a secondary metric.

## 3N-TE — TransactionEngine
TransactionEngine remains the single economic-settlement coordinator; LedgerService stays pure arithmetic; ActorEngine stays the persistence gateway; domain engines decide transaction intent. Never claim atomicity Foundry does not provide; keep success / verified rollback / compensation / refusal / indeterminate distinct; never report `rolledBack:true` without verification; never auto-retry an indeterminate outcome; no second ledger or schema change without tested migration. Steps: TE.1 responsibility inventory (KEEP_PUBLIC_COORDINATOR, EXTRACT_PURE_HELPER, EXTRACT_INTERNAL_SETTLEMENT, EXTRACT_INTERNAL_RECOVERY, DELEGATE_TO_LEDGER_SERVICE, DELEGATE_TO_DOMAIN_ENGINE, CONSOLIDATE_DUPLICATE, RETAIN_*, VERIFIED_OBSOLETE); TE.2 validation/plan building; TE.3 receipts; TE.4 shared settlement lifecycle; TE.5 verification/compensation (prefer targeted recovery over whole-actor restore); TE.6 multi-actor transactions (document real guarantees; no false cross-client lock); TE.7 legacy `execute()`/PlacementRouter reachability check (F-STO-007); TE.8 facade. Required failure-injection tests: purchase/droid/vehicle/insufficient funds/credit adjust/transfer/resale/customization; failure after debit; failure after item creation; failed compensation; failed snapshot restore; duplicate request; retry after indeterminate; GM rollback; already-rolled-back receipt; concurrent unrelated change; identity after recovery. Phase 3P gets a dedicated TransactionEngine section.

## 3N-DC — DerivedCalculator mechanical accuracy
One authoritative calculation per mechanic; every contribution applied exactly once; breakdown sums equal totals. Confirmed defects to reproduce first, then fix with failing-before/passing-after fixtures:
- **P0** half-level: skills use ½ *character* level, personal weapon damage uses ½ *heroic* level, defenses use heroic level (Core Rulebook, Combat ch. p.145; keep the source-distinction note). Keep `level-split.js` as the one level authority; add `getHalfCharacterLevel`/`getHeroicHalfLevel`; migrate every caller of `getEffectiveHalfLevel` (derived-calculator, combat-stat-rules, skills-reference, enhanced-rolls, combat-feat-damage-rule-resolver, houserule-block-mechanic, any others) by the rule each implements; retire the ambiguous helper. Fixtures: Soldier 1/6, Nonheroic 4, NH4/Soldier 2, NH10/Soldier 5. Statblock NPCs keep published totals.
- **P0** condition-track penalty counted in both ModifierEngine defense modifiers and DefenseCalculator; expected defense 20 -> 20/19/18/15/10 over steps 0–4.
- **P0** Skill Focus corrected both in DerivedCalculator and by the runtime `computeAll()` wrapper in `force-suite-runtime-repairs.js` (F-ACT-015): single canonical calculation, remove the wrapper, keep unrelated Force repairs.
- **P0** armor check penalty from `resolveArmorUsageEffects` via ModifierEngine and again read from actor/derived state.
- **P0** DerivedOverrideEngine dotted-key overrides vs full defenses object (base 18 + 2 must be 20); prefer typed ModifierEngine contributions; one result shape for both application paths.
- **P0** current HP of 0 replaced by max (truthy fallback); keep history-preserving HP accounting authoritative; audit/retire `HPCalculator.calculate()` only after consumers migrate.
- **P1** BAB estimation fallbacks must not be presented as certified; ability-source precedence; Damage Threshold single authority (enhanced formula ambiguity -> owner decision, not invention); grapple/initiative single formulas; current-pass dependency ordering; cache signatures (flags, house rules, mannequin isolation); ActorEngine vs `_computeDerivedAsync` result parity and stale-async protection.
Certification states: SOURCE_VERIFIED, IMPLEMENTATION_VERIFIED, OFFLINE_TESTED, FOUNDRY_TESTED, CERTIFIED, BLOCKED. Full calculation census (CANONICAL_AUTHORITY, CANONICAL_DELEGATE, READ_ONLY_CONSUMER, CONTEXTUAL_CONTRIBUTION, DUPLICATE_FORMULA, COMPATIBILITY_DEBT, UNREACHABLE, UNVERIFIED), rulebook-backed regression matrix, semantic guards against reintroduction, tranches DC.1–DC.10, and a Derived Mechanical Authority Certification Report are a **hard gate** before 3N-PRG. Skill-calculation logic may be isolated but not redesigned (no Skills V2).

## 3N-PRQ — Canonical prerequisite authority
Chain: AbilityEngine -> PrerequisiteChecker (compatibility facade) -> PrerequisiteNormalizer + ActorPrerequisiteSnapshot -> **PrerequisiteEvaluator (sole interpreter)**. Public APIs preserved (`evaluateAcquisition`, `evaluatePrestigeClassAcquisition`, `checkFeat/Talent/ClassLevel/PrestigeClassPrerequisites`; result fields `legal, eligible, missingPrereqs, missing, blockingReasons, reasons, unresolved, advisory, warnings, evaluation`). Outcomes: VERIFIED_ELIGIBLE, VERIFIED_INELIGIBLE, UNRESOLVED, EVALUATION_ERROR — never interchangeable; unknown clause is never satisfied; empty list is valid only when authority confirms no prerequisites. Verified defects to fix: prestige `species` list normalized as AND instead of one OR group; `droid_systems` emitted with no evaluator handler (use `droid-part-schema.js`); armor proficiency inferred from feat-name text (Armored Defense is not Armor Proficiency); legacy `prerequisite-checker.js` returns success for unknown conditions; `finalization-prerequisite-validator.js` allows evaluation errors as warnings; independent BAB computations in the legacy checker, snapshot and `prereq-adapter.js` (use BABCalculator; unreconstructable history => unresolved, never fabricated). Preserve scoped feat identity, talent UUID-first identity (Phase 3G), `prestigeClassLevelThreshold` settings, acquisition-time legality, manual-acquisition advisory-by-default policy (`acquisition-authority.js`), explicit auditable GM overrides. Retire legacy evaluators only after differential tests per rule family; no "either evaluator says yes". Tranches PRQ.1–PRQ.10. Supplement: PRQ-canonical-prerequisite-registry.md (generated UUID index; PRQ.0A census already produced).

## 3N-PRG — Unified progression mannequin
One simulated character state (immutable starting state + current draft selections, rebuilt each time) feeding DerivedCalculator, prerequisite evaluation, the summary rail (ProjectionEngine/SelectedRailContext) and finalization preflight. Built on the finalizer's own plan compilation (`dryRun`/`_compileMutationPlan`) applied non-persistently; zero persistence (no world actor, items, settings, credits, FP/DP, chat, receipts); isolated cache identity and stale-preview cancellation; partial builds report pending, never invented defaults; max-vs-current resources preserved; parity harness against the real finalization path for Level 1, level-up, multiclass, prestige; then retire duplicate preview formulas in `summary-step.js` (`_computeProjectedBAB`, defense/grapple/ability-mod projections) and the `prereq-adapter.js` actor construction. Stages A–G; completion report with 14 items.
