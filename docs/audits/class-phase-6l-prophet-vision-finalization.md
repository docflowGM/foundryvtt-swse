# Phase 6L — Force Disciple Prophet immediate choice

**Source:** *Saga Edition Core Rulebook*, printed p. 215 (Force Disciple, Prophet).  
**Parent:** Phase 6K stacked class-feature branch; not a production merge.  
**Status:** UI-to-existing-level-up-planner integration, **NOT live Foundry-certified**.

## Printed behavior
Each Force Disciple class level grants **two** Destiny Points instead of the normal **one**. Immediately at that level-up, the character may sacrifice the extra point and receive an instantaneous **GM-defined** prophetic vision, after which the GM can approve a vision-related new Destiny. Neither the vision's contents nor suitable new destiny can be inferred automatically.

## Implementation
- Existing pure `planForceDiscipleProphetAward` and `ProgressionEconomyPlanBuilder` remain the sole resource and entitlement planner. The ledger lives at `flags.swse.forceDiscipleProphetAwards` and is applied in the same ActorEngine mutation plan as the class advancement.
- New `promptProphetVisionDecision` is called only by `ProgressionFinalizer.finalize` **before** `_compileMutationPlan`, never by dry-run. It requires a validated Force Disciple level-up manifest and an actor with an explicit Destiny. The player chooses **keep both points** or **sacrifice the extra for GM vision**.
- Cancel or close throws before mutation. A previously recorded choice for the **same class level** is reused; a stale choice for another level does not apply.
- Result stored in current `progressionSession.draftSelections.prophet` for the canonical finalizer's existing selection bridge. No direct `actor.update`, no second Destiny award.
- GM vision content and possible new destiny selection remain adjudicated by the GM. The existing Prophet award ledger explicitly marks `pendingGmVision` instead of creating a Destiny or performing a hidden resource spend.

## Test and acceptance
`tests/class-phase-6l-prophet-vision-choice.test.mjs`: destination eligibility, two-vs-one award plans, cancellation without side effects, deterministic reuse, and finalizer ordering.

### Live Foundry test matrix — required before merge
1. With a real Destiny and existing Force Disciple levels, level to 1 through 5 and verify a single prompt each level.
2. Keep points, finalize, verify exact total +2 and one level-keyed award. Reopen/re-run; verify no duplicate.
3. Sacrifice one, finalize, verify exact +1 and pending GM vision. GM narrates vision; no autogenerated destiny.
4. Cancel, backtrack, use another class, or have no Destiny: no false award, prompt, or mutation.
5. Inject ActorEngine failure and verify rollback of both Destiny points and ledger.
6. Reload actor/scene and verify level-up ledger and GM pending status survive.

**Known boundary:** no dedicated GM vision completion UI or automatic destiny substitution. The printed vision and suitable new Destiny are **GM adjudicated**, not a claim of automated completion. The repo's generic non-Disciple Destiny Point baseline is still outside this change.
