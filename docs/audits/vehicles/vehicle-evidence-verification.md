## Read this first: what "verified" means here

**The source PDFs are not in the repository or the session container.** Only the OCR text corpus (`reference/sourcebooks/*_djvu.txt`) is available, so this pass could **not** validate any conclusion against a PDF page. Facts are therefore graded: `TEXT_CORROBORATED` (the record and the legible OCR text agree) is the strongest status used, and **0 facts are PDF-confirmed**. Every group still needs its printed page checked; section "PDF checklist" lists 114 vehicles with publication, printed page and the decisions each feeds. Where a source is "silent", that means the canonical record certifies silence and the text corroborates it - never that the PDF was re-read.

Table 10-2 itself is an image in the corpus, so V100-02 could not be advanced from text at all.

### V100-01 - Stock launchers: may a printed Payload define the ammunition pool when no launcher count is printed?

**1. Exact published evidence**

- Published: a standard proton torpedo launcher holds three torpedoes; concussion launcher capacity is light 6 / medium 16 / heavy 30 (Starships of the Galaxy, Launchers entries, pp.45-46). These are properties of a LAUNCHER.
- Published: the statblock Payload line is the vehicle's complement of grenades, rockets, missiles and torpedoes (Core Rulebook statblock key). It is a carried complement.
- Of the 64 groups, 60 attack lines name only the ammunition ("proton torpedoes +14"), 2 use a singular launcher noun and 2 a plural without a number; no statblock text shows a launcher count (58 located, 0 numeric).
- Payload is corroborated in the text for 54 groups (3 inside a multi-ammunition line); 3 show no payload line, 1 a different figure and 6 could not be located (all 10 need the PDF).

**2. Resolved by source research (conditional on the PDF)**

- 3 groups carry a printed hardwareCount in the record but are named by their ammunition, so the gate does not read it as a launcher count: the PDF decides what that figure counts (3 would run if it is a launcher count and nothing else blocks them).
- 14 groups have a launcher count nobody has reviewed (record value null, not "silent"): a PDF check may find a count (13 would run) or confirm silence.

**3. Genuinely silent**

- 47 groups: the record certifies the source silent on the launcher count and the text corroborates it. 41 of them have no other blocker.

**4. Requires a project-owner ruling**

- Only the genuinely silent groups: whether the Payload alone may define the pool.

**5-6. Options, consequences and conditional unlock (after verification)**

| Option | Description | Conditional unlock |
|---|---|---|
| 1 | Project convention STOCK_POOL: the printed Payload is the pool (no magazine, no reload) for stock groups whose launcher count the source does not print. Executes, but is labelled a project convention, never canonical. | 41 groups; 0 vehicles gain a first executable weapon; 38 vehicles become fully executable |
| 2 | Keep requiring a launcher count (source-printed or GM-certified). No change; these groups stay GM-configured. | no canonical unlock |
| 3 | Both: canonical where a count is printed after the PDF check, STOCK_POOL convention where the source is silent, GM configuration otherwise. | canonical share = the two source-research rows above; convention share = the silent row |

Consequences: Option 1 changes what "executable" means for ammunition (launched rounds are drawn from the Payload with no per-launcher magazine); installed launchers are unaffected. It must be reported as its own outcome so canonical coverage is not inflated.

**7. Recommendation (explicitly UNAPPROVED):** option 3, with a distinct STOCK_POOL_CONVENTION outcome. The text shows the book defines Payload as a carried complement and capacity as a launcher property, so the Payload alone does not establish a launcher count; do the PDF check on the 17 unreviewed or numeric-count groups first.
