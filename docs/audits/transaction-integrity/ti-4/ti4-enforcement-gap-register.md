# TI-4 Phase 0 — Enforcement Gap Register

**Status:** read-only design input. Nothing here is implemented. Each gap names the *smallest* enforceable correction as a `DESIGN_PROPOSAL`; none is authorized.
**Labels:** `SOURCE_VERIFIED` (code read), `†` coordinator re-verified the cited lines, `RUNTIME_UNVERIFIED`, `OWNER_DECISION_REQUIRED`. Path IDs (`Pnn`) refer to `ti4-authority-inventory.md`.
**Severity** is the integrity consequence, not a rules judgment: **S1** an authoritative resource can be duplicated, lost or silently overwritten through a reachable path; **S2** failure is reported wrongly or recovery evidence is absent; **S3** hardening/consistency.
**Packages:** A contract · B identity/replay · C boundary enforcement · D cross-domain tests · E L2/L3 (see roadmap). `C0` = bounded defect corrections inside an existing authority (proposed as the first implementation step).
